# Screen-Link 传输规范 v0.2

消息格式见 `screen-link.schema.json`，本文件只讲怎么传。v0.2 加的是版本协商与对话通道，其余没动。

## 拓扑

手机 App 是**服务端**，展示端是**客户端**。反直觉，但正确：App 是数据源，且展示端不需要被外部寻址。

```
展示端(1.75-B)  ──Wi-Fi──►  手机 App (WebSocket, :8443)
      │
      └──Wi-Fi──►  小智官方云（语音 ASR/LLM/TTS，与上面完全独立）
```

两条 Wi-Fi 连接走同一个 AP，互不依赖。见 DECISIONS D2/D4。

## 通道

| 通道 | 协议 | 用途 | 频率 |
|---|---|---|---|
| 控制面 | WebSocket (`ws://`) | `hello` / `state` / `event` / `command` / `ack` | state 1 Hz；event 即时 |
| 对话面 | 同一条 WebSocket，不另开端 | `dialog`（契约 v2） | 说话时；静默时 0 |
| 批量面 | 暂未实现。`track_pull` 现在只在契约里占位，轨迹数据还没给展示端读 | 按需 |

## 会话建立

1. 展示端启动 → 读配网信息 → TCP 连 `:8443`
2. 展示端发 `hello`，带 `screen_id` / `fw` / `dock_type` / `protocols`
3. App 校验 `screen_id` 在白名单 + `protocols` 与本端 `SUPPORTED_VERSIONS` 有交集 → 回 `ack`，开始 1 Hz `state` 推送
4. 版本不兼容或 id 不认识 → App 直接 close（policy code 1000），展示端显示黄屏而不是崩溃

### `hello` 里的电量与底座

`battery_mv` 现在真的会发，但它的语义比字段名窄，用之前得知道三件事：

- **一次连接只读一次**：值在 `send_hello()` 里现读，所以断链重连之后带的才是新数。中途换电池**不会**推给 App —— 契约里没有第二帧承载它。要在屏上持续报电量，得往 `state` 里加字段，那是另一轮改契约。
- **省略而不是发 0**：没装电池 / 没读到 / 系数没对上时这一项整块不进帧。App 侧 `batteryMv == null` 显示的是「外接供电」，发 0 会被读成「电池空了」，两者在展台上是完全不同的两句话。
- **毫伏值未经标定**：固件按 AXP2101 的 1.1mV/LSB 折算，但厂商例程把同一个原始值当纯 mV 打印，两份说法冲突，实机接上电池后必须拿万用表量 BAT 座两端对一次。对不上只改固件那一行，不改契约。

`dock_type` 目前还是固件里写死的字符串，板上没有识别底座的电路。**别照"8PIN 分压电阻 + ADC"去做**：
8PIN 引出的 GPIO16/17/18 在 ESP32-S3 上属于 ADC2，而 ADC2 与 Wi-Fi 共用、联网时官方不支持采样，
这条板上唯一常驻的联网方式就是 Wi-Fi。真要做硬件身份，两条可行的：
① 三个脚当输入 + 内部上拉，底座把其中几个短接到 GND → 3 位编码刚好盖住 `dock_type` 的 7 个取值；
② 干脆不 sensing —— 底座是谁装的就是谁，由 App 在配对时选，`dock_type` 走 `command` 下行写进 NVS。
在只有 1-2 个底座之前，②是正确答案。

## 版本协商

**协商看 `hello.protocols`，不看帧上的 `v`。** 两个原因：出站帧走了 `encodeDefaults = false`，`v` 不总是写出来；更要紧的是老固件本来就不懂 `v` 是什么，拿它当依据等于要求对端先升级才能被识别。

- `protocols` 省略 = **不申报** = 按 v1 待。这条默认值不能是当前版本，否则新加一档时所有老固件都会被误判成新固件
- 取双方都支持的**最大值**作为本会话协商结果，记录在连接上（`ScreenLinkServer.negotiated`）
- v1 → v2 **只多一种帧**（`dialog`），state / event / command / ack 一字节未变。所以 v1 固件不用升级也能继续看状态，只是这台屏不接对话
- 逐连接过滤：`broadcast` 时版本 < 2 的连接收不到 `dialog` 帧。不然老固件的解析器会撞上一条它不认识的 `t`

## 对话通道（契约 v2）

这条是这次加的重点，因为它决定了一个产品问题：**"跟车说话"这件事的主场景在圆屏，而对话记录的宿主在手机。**

为什么宿主必须是手机，三条都成立才敢这么定：

1. 对话要回答的全是状态类问题（车到哪了、还剩几条额度、下次过境几点），**事实全在手机那台状态机里**，屏侧只有 1 Hz 的投影，拿投影答题就会答出过期话
2. §6.1 那条文案红线只约束过网关的话。宿主在屏侧，闸就管不到记录里
3. 用户明确要求在手机上看到圆屏那一侧的对话 —— 反过来（宿主在屏）就做不到这条

所以屏是**耳朵和嘴**，手机是**记性和闸**。落到线上是这几条规矩：

```
屏上按住说               手机里问                    手机主动播报
   │ dialog{dir:up}         │ 直接进记录                 │ 进记录
   │ origin:screen          │                            │
   ▼                        ▼                            ▼
  手机 AiGateway 答题 → ConversationLog（唯一事实源）→ dialog{dir:down} 回镜到屏
```

- **每一句都进同一条时间线**，不分"这轮的记录在谁那儿"。屏断线重连后不自己补历史，由手机把最后几轮重新推下来
- **镜像是不对称的**：手机起的一轮，问和答都要回镜（站在车那边的人只看见答，读不出这是在答哪句）；圆屏起的一轮，那句问话不回镜（屏自己已经画过了，再回一遍就是同一句话出现两次）。**代价说清楚两条**：① 屏和手机上的行数可以不一样，以手机那条为准；② 这条判断只看"这一轮是谁起的头"，不看连接，所以**两块屏同时接入时 B 屏看不见 A 屏那句问话**，只看见答。演示就一块屏，量产要改成按连接回镜（把 `origin` 换成连接 id）——那时候顺带要回答"两块屏的对话是不是同一个会话"，别顺手改一半
- 去重键是 `turn_id + dir`。`turn_id` 由**起头那一方**生成，另一方沿用它。**它必须全局唯一、跨重启唯一**：宿主的记录按它去重且这份记忆跨连接有效，屏那边要是用纯自增的 `s-0`，页面刷新后就从头编号，撞上旧 id 的那几句会被当重复直接吃掉，表现是"重连之后头几句问了没反应"。冒充件的做法是 `s-<开机随机段>-<自增>`
- **出站帧走 `encodeDefaults = false`，等于缺省的字段不上线**（`source: local_rule` / `origin: screen` 会被整个省掉）。所以收的一方必须自己补回同一套默认值 —— 屏那边读到一个 `undefined` 的 source，角标就会一路掉进兜底档，把"未接模型"显示成"手机起"。这条两边都要记：JSON 里省掉不等于对面知道 —— 屏那边靠它把答钉回原来那一轮。主动播报每轮都要换新的 `turn_id`（带时间戳），否则冷却后的第二轮会被去重当成重复丢掉，表现是"屏上听得见、手机里没记录"
- `dir: down` 的帧**只补记录，不再触发答题**。少这一条，屏和手机会互相把对方的话再问一遍，无限对答
- `source` 逐条标，不整块标一次。`xiaozhi_cloud` / `muse_cloud` 是同一类：那句话是**屏那侧的云**替我们说完的，**只入账、不触发我们的技能、不回镜**。把别人的输出当问题再喂一遍网关，等于让别人决定我们要不要发卫星报文。
  换到 Muse 底座以后 `muse_cloud` 是主来路（屏本机那条 ASR→云→TTS），`xiaozhi_cloud` 留着给还没换底座的那版固件。
  **屏这边要做的两件事**（组件都已经有口子，缺的是接上）：
  ① `screen_link_send_dialog_up()` 已经有了，但 Muse 那版 `carpet_page.c` 一次都没调用过 —— 于是孩子对着屏说的话，手机的时间线里一条都没有，"家长在手机上看到孩子问了什么"这条产品话现在是空的。
  ② 上行的那条 `source` 要填 `muse_cloud`，别省着不填。省了它，手机会按默认档 `local_rule` 记成"我们自己的规则答的"，那个标就是假的
- 对话帧不设 ACK、不重发。它和 `state` 一样容忍丢失：丢了这一句，屏上少一行，手机那条记录还在。**别为了几行聊天文字给对话面加一套重传**，那套的正确性成本比它救回来的显示成本贵

**当前是明文 `ws://` 而不是 wss。** 理由和补偿控制在 DECISIONS D8，一句话：圆屏侧连自签证书要引 TLS 栈并关掉校验，换来的实际安全性接近 0，工程量却会把 W2 吃掉。补偿是「默认拒绝接入 + screen_id 白名单 + 只在演示时开」三层。量产前这条必须重评。

## 保活与断线

- App 每 1 Hz 发 `state`，这本身就是心跳。**3 s 没收到 state，展示端把链路图标变灰**；10 s 没收到则重连
- 展示端不主动发心跳，省流量省电
- 重连退避：1s / 2s / 5s / 10s / 30s 封顶
- 断线期间展示端**保留最后一帧 state 并打灰色水印「链路中断 mm:ss」**，不要黑屏。演示时黑屏等于事故。
  数据保留最后一帧，但**卡面**连续 10s 没声就落回钟面 —— 理由和边界见下面「断链够久」那一节

## 可靠性

- `event` 必须回 `ack`（带 `for_event_id`）。App 3 s 未收到 ack 重发一次，再 3 s 放弃并记日志
- `state` 不重发、不去重，靠 `seq` 单调递增检测丢帧。丢了无所谓，下一秒就是新的
- 展示端按 `event_id` 去重，保留最近 32 个 id（环形缓冲，够小）。**这个环跨重连不清空** —— 屏不重启它就一直在。所以 id 必须**全局唯一**而不是"本次进程唯一"：App 重启后 seq 归零，`evt-0..evt-31` 会整批撞上屏上还留着的老 id，被当重复静默丢掉，丢的那条可能是 `sos_acked`。两侧各自的写法：App `evt-<启动标签>-<seq>`、屏 `scr-<启动标签>-<seq>`；长度上限 39（屏侧 `EVENT_ID_MAX` 减一，超了 `strncpy` 截断，两个 id 会共用一段前缀）

## 页面归屏、内容归手机（2026-11-04 两台机器商定）

这一节改的是**权**，不是字段。定下来的四句话：

| | 归谁 | 走哪条 |
|---|---|---|
| **在哪一页**（L0 脸 / L1 选场景 / 车载 / 亲子 / 数字分身 / 时钟 / 图片） | **屏** | 触摸直接切，不等手机往返；切完通报一条 `page_report` |
| **这一页里说什么**（卫星倒计时、答句、状态总览、那张脸） | **手机** | 还是 `state.ui.card` / `ui.emotion`，1 Hz 那一帧 |
| **盖住一切的那件事**（SOS 确认 / 平台回执 / 越界） | 手机发起，**屏执行** | `event`；这是唯一允许服务端抢占的一档 |
| **谁在跟谁说话**（每一轮问答） | **手机**（唯一事实源） | `dialog`，见上面那节 |

为什么这么切，三条都成立：

1. **一次触摸不能等一个往返。** 页是手上那个动作的直接后果；绕手机一圈，快的时候 200ms、
   链路刚掉的时候 30s —— 后面那一种是"屏按了没反应"，而这正是我们已经在 #36/#42 修过两轮的那类现象。
   内容不一样：内容由**车里正在发生什么**决定，而那些事全在手机那台状态机里。
2. **两侧各自定页会讲两件事**这件事不成立，各自定内容才成立。页是本地可见的（玻璃上就是它），
   内容是要判断的（该说倒计时还是该说越界）。判断权留在有事实的一侧，翻页权留在有手指的一侧。
3. **手机上那块镜像必须跟着页走。** 首页那枚圆画的就是推给屏的这一帧；屏已经在亲子页、
   手机上还写着"屏在状态盘"，观众先怀疑的是屏坏了 —— 所以回声这一档不是可选项。

### `page_report` 是通报，不是申请

这条区别是**整套分权的全部代价所在**，两边都要写进代码而不只是文档里：

- 屏切完页发 `command{cmd:page_report, args.page:"kids"}`。**手机不许驳回、不许改判**：
  `DemoRuntime.reportScreenPage()` 只做两件事 —— 认得出就存下来并回声进 `state.ui.page`，
  认不出就记一行日志、值不动。
- 认不出来的页名**一律拒收**（`ScreenPage` 就那七个）。这条不是防御性代码：Muse 底座自己那套
  tile 里就有 `settings` 这个名字，将来底座加一页而契约没跟，表现是屏自己切过去了、
  手机上那一格静默停在上一页。所以 `:core` 有两条断言钉它（`ScreenCommandTest`）。
- **组件那道闸已经放行**：`screen_link.c` 的 `ALLOWED` 里加了 `page_report`。
  固件那边不用改闸，只要发。
- `card_set` 和 `page_set` 都不在契约里，是**刻意**不在：前者会把内容判断权下放给没有事实的一侧，
  后者会把刚交出去的翻页权又要回来。`SchemaDriftTest` 两条都拦。

### 手机上那一格读什么

`DemoRuntime.Status.screenPage`。null 有两种，都不许用旧值填：
**老固件不会报**，和**屏刚重连还没补报**（屏断线时手机会把它清成 null —— 屏不在了还写着
「屏在亲子」是那块镜像能编出的最贵的一句假话）。App 首页对应文案是「屏没报它在哪一页」。

### 屏重连之后必须补报一次

`page_report` 只在**页真的变了**的时候发。少了补报，重连之后手机上那一格会一直空着，
直到下一次真的翻页才复明。所以建链成功（`hello` 发出去）之后要立刻报一次当前页 ——
`simulator/screen.html` 已经按这个跑，固件那侧对应 `screen_link` 的 hello 之后同一个调用点。

### `dialog.action`：语音拉起场景，只跳页

```
家长在屏上说"给孩子放首歌" → dialog{dir:up, source:muse_cloud}
  → 手机答题 → dialog{dir:down, text:"…", action:kids}
  → 屏翻到亲子页，再回声一条 page_report{kids}
```

- **只允许挂在 `dir=down` 上**，挂在上行会被手机端剥掉（屏不能给自己下命令，那条边界不许绕过）。
- **只做换页这一件事**：它不是技能口、不是 SOS 口。所以"云端代答的一句话替车主按下了呼救"
  在这条契约里构造不出来 —— 这也是为什么它值得挂在已经存在的对话帧上，而不是新开一种帧。
- 对话面不重发。丢了这一条 = 屏停在原页、手机记录仍在，这正是要的降级。
- **生产者还没有**：跳页要靠命中的技能给出一页，而 `:core/ai` 技能表里现在七条全是卫星/车辆那一路。
  亲子那一条进来之前，这一档只有屏侧那半（`simulator/screen.html` 的 `applyAction()` 已经实现）。
  **别把它当成"已经通了"去讲**

### 版本：不升

没有新的 `t`，三个字段全是可选加性的，`hello.protocols` 仍谈 1/2。老固件继续看状态、继续能对话，
只是不会报页（手机上那一格空着）也不认 `action`。这是 v0.2 的第三轮加性修订，契约号没动。

## 上行：屏只能请求，不能决定

- `command` 那三条交互用的取值（`card_next` / `card_auto` / `poke`）**都是请求**：屏只说"用户在这块玻璃上做了什么"，
  画哪一张卡、画哪一张脸仍由手机算出来写进 `state.ui.card` / `ui.emotion`。
  **这一节只管内容那一半**（见上面「页面归屏、内容归手机」）：同一根手指翻页不归这里管，那是 `page_report`
- 为什么不给屏一个 `card_set`：定卡权一下放，同一辆车就会在手机和屏上讲两件事，而 §6.1 那套文案红线只约束得过网关的那一路。
  请求制还留了一个**拒绝对**：SOS 正在 `armed`/`pending`/`sent` 的时候 `card_next` 被顶回来，
  观众不能把卫星卡滑走 —— 那种时候屏上唯一该说的话是倒计时
- `card_auto` 是手动钉住之后唯一的出口。钉住的入口有两个：App 设置页那个选择器，和屏上的左右滑
  （每一条 `card_next` 都会把卡钉在算出来的那一张上）。所以屏也必须有一条交回的路，不然滑两下之后
  这块屏就再也不跟着车里的事变了 —— 固件那侧用的是**长按卡面**（≥800ms）发 `card_auto`
- 屏发的每一条都必须过组件里那道合法值闸（`screen_link_send_command` 的 `ALLOWED`），非法值当场退回、绝不上线：
  手机端解不开入站帧的处理是**关连接、一句话不说**，屏这边只表现为"按了没反应、过几秒掉线"
- 这四张表由 `:core` 的 `SchemaDriftTest` 逐条比：schema 的 `command.cmd`、Kotlin 的 `CommandType`、
  固件的 `COMMAND_NAMES`、组件的 `ALLOWED`。
  **比不了的那一半要说清**：`COMMAND_NAMES` 在 `firmware/screen/app/main/app_main.c` 里，而那棵树
  从没进过仓库（只在写它的那台机器上）。这条断言在别的机器上是**明着 skip**，不是绿。
  Muse 那一路改比仓库里就有的 `firmware/screen/muse/muse-carpet.patch`：补丁里 `CMD_NAMES` 那三条
  必须既在 schema 里、又过得了组件那道闸。老树要真想留作回滚，就把它提交进来，别让它当"看不见的守卫"

### 这块玻璃上的手势（固件 #42）

阈值都是固件自己按按下点/松手点算的，不走 `LV_EVENT_GESTURE`：那条只发给被按住的对象，
且链路上任何一层可滚容器都会把滑动吞成滚动。60px≈5.7mm（266dpi），是"有意滑动"和"擦个灰"的分界。

| 动作 | 上行 | 本地 |
|---|---|---|
| 左右滑 ≥60px | `card_next`，`args.dir` = +1（往右）/ -1（往左） | 什么都不改，等手机的下一帧 `state.ui.card` |
| 上下滑 ≥60px | 无 | 上滑展开、下滑收起当前卡的明细层（定开/定关，不是 toggle） |
| 单击 | `poke` | 什么都不改 |
| 长按卡面 ≥800ms | `card_auto` | 什么都不改 |
| 长按那颗圆钮 ≥1500ms | `sos_press` | 进度环 |

一次触摸只认一个动作，所以本地什么都不改的手势才敢只发一条上行。

**单击不再切明细**（这一条从 #42 起改了，固件和彩排冒充件都要按这个走）：契约里 `poke` 就是单击，
而手机收到 poke 会把卡切成表情卡并留 8 秒。同一根手指既展开明细、又把整张卡换掉，
展开的那 6 行 1 秒内就随旧卡一起消失 —— 屏上看着像"我点了一下它自己乱跳"。
明细层因此改给上下滑这条确定的手势，单击只负责"我在玻璃上动过"。

### 断链够久：屏自己落回钟面（唯一允许固件挑卡的一档）

`firmware/screen/app/main/app_main.c` 的 `offline_clock_due()`：连续 10s 没听到有效 state
（连着但 >3s 没帧、或套接字断了在退避，两种算同一个数），屏就把卡换成 `clock` 本地画。
写死在契约里，是因为两侧各自猜就会讲两件事：**这是屏唯一一次可以自己挑卡，别的地方都不许。**
（"挑卡"指内容那一半。挑**页**是另一件事，那一半归屏，见「页面归屏、内容归手机」——
这一档说的不是"屏不许自己动"，是"屏不许自己决定替手机说哪句话"。）

- 为什么是钟：继续挂着一张不再更新的卫星倒计时，是在替一个已经联系不上的手机维持一句它没法负责的话；
  钟至少还是屏自己给得出的东西（停在最后一帧，钟面第二行会写"链路停了 · 停在最后一帧"）
- 为什么不是状态盘：那张盘上每个数都来自手机，断了就全是旧的，看着比钟更像"一切正常"
- 为什么阈值是 10s：和组件自己掐线重连那个数对齐，屏跟的是"这条链路已经被判定死亡"那一刻；
  比契约里 >3s 变灰晚，是因为变灰只是"可疑"，还不值得换掉整块屏在说的话
- 一次都没连上过（`seq==0`）**不走这档**：那时钟面只有 `--:-- 还没有一帧`，
  而状态卡那句"等手机接入"才是观众能照着做的事
- 链路恢复后手机的第一帧 `state.ui.card` 立刻把卡抢回来，不需要屏做任何决定

## 安全边界

这套服务能读车主位置，而现在是明文传输、无认证。所以：

- 监听 `0.0.0.0:8443`，但 `accepting` 默认 false —— App 上不打开了「允许展示端接入」，任何连接进来立刻 close。这比 bind 127.0.0.1 弱一点（端口对外可见），但省掉了「演示现场还要先进设置页改绑定地址」这条必错路径
- `hello` 必须携带预共享 `screen_id`（出厂烧录，App 侧白名单），不在白名单直接断
- 关掉开关时**主动断开已有连接**，不是等它自己超时
- **对话面上的是同一条明文链路**，所以那个开关现在的含义变重了：它不只放开位置，还放开车主说出去的话。演示现场AP尽量自己开，不要连商场地场的公共 Wi-Fi
- 红线一（§6.1）在两侧各守一次：手机过闸后才入记录，屏在画出来之前再过一次。**屏那一次不是重复劳动** —— 小智官方云那条路是它自己往屏上画的，手机的闸管不到，而现场冒出一句「救援已在路上」是不可挽回的那种错
- 演示结束后关掉，或 App 退出即关（`MainActivity.onDestroy` 里 `shutdown()`）
- 不要把这套服务部署到公网。**任何情况下都不要。** 需要远程查看就等真正的业务后端
