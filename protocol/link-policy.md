# 4G / 卫星 链路切换策略 v0.1

架构文档 §1.3 写了「信号强度 > 阈值 走 4G，< 阈值 走卫星」，但**阈值和滞回都没定义**。这条不定死，W4 的「4G/卫星自动切换」没法写，而且演示时会出现来回抖动的尴尬画面。

## 状态机

```
        ┌──────────────┐
        │   CELL       │  主链路=4G/5G，GT1005 待命省电
        └──────┬───────┘
   cell_bad 持续 20s
        ┌──────▼───────┐
        │   PROBE      │  试探：发一个 20B HEARTBEAT 走卫星，等 ACK
        └──────┬───────┘
   卫星 ACK 成功 或 cell 仍差 60s
        ┌──────▼───────┐
        │   SAT        │  主链路=卫星，SFQ 心跳为主
        └──────┬───────┘
   cell_good 持续 30s
        ┌──────▼───────┐
        │   RECOVER    │  补发离线缓存，同时把星历 update() 拉一次
        └──────┬───────┘
        回到 CELL
```

四态而不是两态，是为了让展示端有东西可演：`PROBE` 和 `RECOVER` 是两个有戏的瞬间（"正在尝试卫星""正在补发离线期间积累的 N 条数据"）。

## 判据

**不用 RSSI 绝对值**，因为 Android 各厂商 `SignalStrength.getLevel()` 口径不一，且演示机型号未知。用组合判据：

| 条件 | 判据 | 说明 |
|---|---|---|
| `cell_bad` | 满足任一：① `NetworkCapabilities` 无 `NET_CAPABILITY_INTERNET` ② 连续 3 次 5s 超时的心跳探测失败 ③ 信号等级 ≤1 且持续 15s | ①② 是"真不通"，③ 是"预感要不通"，提前切避免丢包 |
| `cell_good` | `NET_CAPABILITY_VALIDATED` 为 true 且一次 HTTPS HEAD 在 2s 内返回 | `VALIDATED` 有缓存，必须真发一个包确认 |
| 探测周期 | CELL 态 30s 一次；SAT 态 10s 一次 | SAT 态要更快发现网络恢复，因为观众在等 |
| 滞回 | 切入 SAT 要 20s 确认，切回 CELL 要 30s 确认 | 不对称。卫星链路一旦占住，重入窗口成本远高于蜂窝 |

**所有阈值集中在 `LinkPolicy.kt` 的一个 data class 里，演示时可通过 App 设置页改。** 因为现场到底什么信号条件不可预测，彩排时大概率要调。

## SOS 例外

SOS 触发时**不进状态机**，无条件双发：

1. 立即 `sendMsgMCQ(SOS)` 走卫星（不等 ACK，不判链路）
2. 同时若 `cell_ok` 走 HTTPS POST 一份
3. 卫星 ACK 超时 60s 后重发，最多 3 次，`flags.bit0` 标双发状态
4. 三次都 `NO_ACK` → 展示端弹红色「卫星未确认，请在开阔处等待下次过境」，并显示 `next_pass_in_s`

第 4 步是演示效果的关键：**即使失败也有内容可看**，不会变成干等。

## 星历依赖

`StarManager.update()` 只在 CELL 态调，且每天最多一次。切到 SAT 态前必须确认星历缓存未过期——否则卫星链路根本发不出去，这是 §8.1 里「星历离线缓存有效期」那条外部依赖的**内部兜底**：

- 缓存年龄 > 24h 且当前在 CELL 态 → 立刻 update
- 缓存年龄 > 24h 且当前在 SAT 态 → 展示端黄字告警「星历过期，卫星可能不可用」，**不要静默失败**
