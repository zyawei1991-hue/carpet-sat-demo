# 亲子内容开源借鉴 —— 给 App 侧的交接单（2026-11-18）

owner 问：「网上有没有适合我们项目的亲子场景的开源项目可以借鉴，补充到圆屏亲子功能中」。
这份是调研结论 + 落地路径。**屏侧一个字不用改**：借的是内容，走的是已经落地的两条通道
（photo_chunk 推图 b56662b + 现有 TTS 念答句），不新增屏上按钮。

## 1. 拍板建议：借 StoryWeaver 的绘本内容，不借任何开源项目的"壳"

**StoryWeaver**（Pratham Books，印度非营利童书出版方）
- 站点：https://storyweaver.org.in ；开源说明：https://open.storyweaver.org.in/
- 13,000+ 本绘本、183 种语言，**全部内容 CC-BY 4.0**（可商用、可改编，**必须署名**）；
  平台代码 MIT（https://github.com/PrathamBooks/sw-core 、sw-web、sw-docker）。
- **没有公开 REST API**（开源页只给了自托管部署和邮件联系）——所以不走"运行时拉 API"，
  走**离线精选**：在站内按语言筛 Chinese 的绘本（中文书目数量没称过，选书时现数），
  人工挑 3~5 本适合 3~6 岁、画面干净的，下载页面图 + 文字，署名信息一起存。
- 用法：App 里「讲个故事」= 把绘本逐页推给圆屏（每页一张图走 photo_chunk，
  配文走现有 TTS 念），翻页节拍 App 定。**这就是把"亲子场景"补实的正路**：
  屏上相册页立刻有真内容可看，而不是摆一个点不动的"故事屋"按钮。

**为什么不借壳**（11-14 owner 已拍，D15.3 不假造 + B §6.5/§8.2）：
Round-Clock 等开源表盘项目的"看图英语/故事屋/电子宠物"格子是死应用壳，
屏上不许摆点了没反应的按钮。内容进来之前，亲子页维持现有三行（对话/过境/安全）。

## 2. 次级借鉴：只借提示词，不借语音链

**xiaozhi-esp32 / xiaozhi-esp32-server**（MIT，GitHub 78/xiaozhi-esp32）：
它的亲子/助手人设提示词可以抄进 App 现有的场景人格映射（941bd54 那套），
让"亲子"场景的答句更贴孩子。**语音链整条仍是我们自己的**（v4 上行 + 硅基流动 ASR +
edge-tts 晓伊，owner 已拍）——不接它的服务端、不换它的协议（A.0 裁决）。

**Espressif 官方绘本故事机参考方案**：只作架构印证（ESP32-S3 + 屏 + 云端 TTS 讲绘本
是成熟路线），不搬代码。

## 3. 署名与合规（CC-BY 4.0 的硬要求）

- 每本用到的绘本记下：书名、作者、译者、来源链接、许可（CC-BY 4.0）。
- App 里故事播放页带一行署名（如「故事来自 StoryWeaver · 作者 XXX · CC-BY 4.0」）；
  圆屏上不摆署名文字（屏不摆死内容），署名留在 App 侧即可满足"适当署名"。
- 改编（压缩文字配 TTS）允许，但不得暗示原作者背书。
- 「你好小安」唤醒词的权利归属仍待 owner 拍（esp-sr README 那条），与本单无关但同属合规账。

## 4. 验收口径

- App 选一本绘本开讲 → 圆屏相册页逐页出图（屏 log `@photo 收齐`）+ 晓伊念配文；
  屏侧接收/解码/轮播已实装（本单同日落地，台架 `>phototest` 可复称）。
- 真机一轮要等带 photo_chunk 的新 APK（装机那版 1.26.0 早于 b56662b，不会推图）。
- 不新增屏上按钮、不新增 App 页面（故事入口挂在现有亲子场景的对话里，
  比如对屏说「讲个故事」由 App 侧人格识别后开讲——识别逻辑 App 定）。
