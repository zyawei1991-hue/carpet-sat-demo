## 三、逐条影响分析

### 1. 英语陪练 + 监护定位
- **英语陪练 = 人格/提示词，在 App/云侧**。屏已有场景人格通道（state 帧），不新增页面、不摆死应用壳（D15.3 / B §6.5 / §8.2 仍有效）。
- **定位屏侧做不了**：屏无 GPS。定位只能手机侧做；屏经既有 event 帧通道显示监护状态即可，无需新硬件。
- 屏侧要补：#24 真人唤醒、#69 守护真帧（见上）。
- 张力点：现有换装/场景环/相册偏娱乐，与「教育而非娱乐」定位有冲突。**保留还是弱化，待 owner 拍**；屏侧都是现成功能，弱化走配置层面，不删代码。
- SOS 待发送时手势冻结是既有行为；儿童产品是否可接受，待 owner 拍。

### 2. 依赖手机 + 云、网络稳定性
- 架构现状已符合：手机 App 是 WS 服务器（须前台），屏拨号。4G 不改屏：手机 4G 开热点照样分享。
- **屏侧真要修的两件**：
  1. 重连退避慢段（#34）：2026-11-19 14:20 实测热点断开后屏退避到每 600 s 扫一次，热点回来最长等 ~10 分钟。儿童产品不可接受，需封顶退避 + 快速重扫。
  2. 断链状态上屏：现在连不上就沉默，孩子不知道发生了什么；应有明确「手机不在身边」提示（屏侧 UI，帧/状态已有）。
- **最大架构问题（待 owner 拍）**：民宿房间是否每房配一台常开手机/平板当枢纽？当前设计 App 必须前台，孩子独处房间无手机则屏无法对话（无离线）。备选：把语音链（ASR/LLM/TTS）搬上屏——大改，需单独评估内部 RAM/算力/成本，**本文不承诺可行**。

### 3. 外壳 + IP
- 屏侧基本不动。IP 授权谈成后 Avatar 换形象 = 换 muse_pixel 像素素材，工作量小；**建议保留现有原创宠物作兜底**（授权到期风险）。
- 硅胶套不得遮挡麦克风/扬声器/触摸；外壳尺寸关联屏型号选择（见待拍板②）。

### 4. 民宿 12-20 开业
- 屏侧出货前验收清单 = 第二节「没称到」四项 + #34 修复。
- 批量部署屏侧已具备：出厂默认 mic AUTO、设备号回读（hello ID）、烧屏防护（常亮展示）、补丁 + 全片刷流程（唤醒模型分区要求**首次全片刷**，不能只 app-flash）。每房配网走「App 一次操作连屏」既有约束。
- 首批屏型号待 owner 拍：1.75 AMOLED 旧屏（稳定、全链路已验证）vs 1.85 LCD 新屏（移植已编完 FEXIT=0 **没刷**，音频方案与 360 UI 几何未验）。

### 5. 广告嵌入
- 广告在答句里 = App/云提示词层，**屏侧零改动**。前期调研阶段屏不做任何广告 UI。
- 数据触达：屏已有上行统计日志（帧数/字节/耗时/turns）；如需遥测由 App 侧收集，屏保持现有回读即可。
