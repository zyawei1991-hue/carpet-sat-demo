## D4 · 展示端数据通道：从「拉云端 REST」改为「直连手机局域网服务」

**状态**：生效 · **需要回写架构文档 §4.2 / §5.3 / §6.1 / §6.2**

原方案里圆屏「Wi-Fi 连云端 REST API 拉数据」。演示阶段不建业务后端，这条不成立，改为：

**手机 App 在局域网内起 HTTP + WebSocket 服务，圆屏直连手机，不经过任何公网服务器。**

- App 侧监听 `0.0.0.0:8443`，自签证书，圆屏侧跳过校验（演示设备，可控）
- 状态推送走 WebSocket（1 Hz 心跳 + 事件即时推），轨迹/地图切片等批量数据走 HTTP GET
- 组网三种模式，按现场条件降级：
  1. 现场有可用 Wi-Fi → 手机和圆屏连同一个 SSID
  2. 现场无网 → 手机开热点，圆屏连热点（Android 可同时开热点并保留蜂窝数据）
  3. 连热点也不稳 → 手机直接 `adb reverse` 或圆屏连手机的第二个 AP，纯局域网，不要公网

**这样做的收益**：地下停车场、野外这些蜂窝断掉的场景，展示端依然能出画面。原方案在这些场景下展示端会白屏——这是评审时标过的缺陷，改完顺带修掉了。

**代价**：圆屏拿不到"云端"数据，所以所有需要跨设备持久化的功能（车主远程查看、多用户、云端轨迹归档）演示阶段一律不做。见 D3。

## D3 · 演示阶段不建业务后端，能力边界确认

**状态**：生效

逐条对照 §5.2 功能清单，判定哪些不需要后端也能满足：

| 功能 | 优先级 | 不建后端能否做 | 落在哪 |
|---|---|---|---|
| BLE 连 GT1005 + SDK 初始化 | P0 | ✅ | App |
| GNSS 定位（手机 + GT1005 融合） | P0 | ✅ | App |
| 4G/5G 位置回传 | P0 | ⚠️ 语义变更 | 原来是"回传云端"，改为"回传展示端"（D4）。卫星那一路仍回时空道宇测试平台 |
| SOS 一键（MCQ + 4G 双发） | P0 | ✅ | 卫星路走测试平台；4G 路走 App→展示端局域网推送 |
| 离线心跳 SFQ 定时 | P0 | ✅ | App 定时器 + 卫星 |
| 电子围栏 + 越界告警 | P1 | ✅ | App 本地算。GeoJSON 存本地，手机 GPS 逐点判断，不需要服务端空间查询 |
| 轨迹记录 + 回放 | P1 | ✅ 降级 | App 本地 SQLite；回放推给展示端。**不做**云端归档和跨天跨设备查询 |
| 卫星过境预测 | P1 | ✅ | 星历 SDK 在 App 端本地计算 |
| 离车哨兵 | P1 | ✅ | App 加速度传感器，本地 |
| 4G/卫星自动切换 | P1 | ✅ | App 本地状态机 |
| 宠物状态（情绪/温度/电量） | P2 | — | 本来就没传感器，不做 |

**仍然依赖外部、但不是"我们自建后端"的三项**（这三项是真正的进度风险，不是工作量问题）：

1. **AI 语音对话** —— 走小智官方云（ASR+LLM+TTS）。要求演示现场能出公网。公共服务器不稳定，§10 已列备选：圆屏只做屏幕显示，语音对话挪到手机 App。**建议 W5 彩排时实测一次，别等到演示当天。**
2. **卫星链路平台侧闭环** —— SOS 被平台收到、平台下发 MCI，依赖 §8.1 的**测试卡 + 测试账号 + SOS 平台侧对接方案**。这是外部排期，W1 就要催，不催就是 W3 卡住。
3. **GT1005 BLE 协议文档** —— UUID / 帧格式 / 分包规则。§10 的对策（先用 RS232 + USB 转 TTL 走有线）是对的，但要注意 SDK 的 `ModuleOperation` 接口只要求 `send(byte[])` / `receive` 回调，**传输层可替换**。所以正确做法是 W1 就把 `ModuleOperation` 的两个实现都写掉（`BleModuleOperation` + `UartModuleOperation`），BLE 文档没到就用 UART 版跑全部业务逻辑，文档到了换一个注入。**这样 BLE 文档延迟不再是阻塞项。**

**明确放弃的（演示阶段）**：车主远程查看、多设备多用户、轨迹云端归档、围栏规则远程下发、SOS 短信/电话外呼。

## D2 · 双通道链路拓扑（先试）

**状态**：试验中，W2 末验证

圆屏和手机之间**结构化状态走局域网 WebSocket/HTTP**（见 D4），**语音走小智云 Wi-Fi**，两条通道独立。

理由：卫星链路本身就是断网场景，展示端的控制面不能依赖公网；但语音流 BLE 带宽扛不住，且小智固件的语音链路是现成的，不改。

**验证标准**（W2 末）：手机 App 杀掉再启动，圆屏画面在 3 s 内恢复链路状态显示；期间语音对话不中断。达不到就说明两条通道有干扰，回退到"圆屏只读 WebSocket、语音降级"。

## D1 · 展示端硬件选型

**状态**：生效 · 已下单

`ESP32-S3-Touch-AMOLED-1.75` **带外壳版（1.75-B）**，不是文档 §1.2/§4.1/§7 里写的 1.75C。

变更原因（评审时确认）：
- 1.75C 只引出焊盘、无 8PIN 排座，且封在 CNC 壳里，做不了模块化底座
- 1.75-B 后盖给 8PIN 排母、SPK、BAT 各开了窗口，接口可外接
- 1.75-G 与带外壳互斥，且定位源本来就是 GT1005，圆屏不需要独立 GNSS
- 两款都在小智固件 `USE_DEVICE_AEC` 白名单内，语音能力等价

**需要回写文档**：§1.2 角色表、§4 整章标题和 §4.1 规格表、§7 BOM 第 2 行、§8.3 样机申请项。

**BOM 补充**：1.75-B 配置清单只有「板 + 8Ω 2W 喇叭」，**电池不随盒**，要另购 3.7V 锂电 + MX1.25 2P 插头线。
