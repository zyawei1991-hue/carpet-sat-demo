# App 设计约定（借鉴 taste-skill）

> 来源：[taste-skill](https://github.com/leonxlnx/taste-skill)（MIT，11万+ star）。它是面向 Web 的技能包，脚本无法直接用于 Android Compose；本文档只平移它的**方法论**，规则按我们 App + 圆屏的实际情况改写。

## 1. 先定方向，再写代码

taste-skill 的核心反模式防御是：AI 默认产出「平均脸」——所有页面长得像同一个 Material 模板。它的解法是每次构建从 20 个设计方向里随机发三张牌，agent 挑一个最合适的再动手。

我们的约定：

**做任何新页面 / 新场景卡 / 大改版之前，先明确说出本页的设计方向，再写代码。** 方向从下面的库里选（可组合，但主方向唯一）：

| 方向 | 一句话描述 | 适合我们哪里 |
|---|---|---|
| 海报化标题 | 文字本身是视觉主体，放大、加粗、占满 | 首页问候区、场景卡标题 |
| 一物居中 | 页面只承载一个核心对象，其余全让位 | 圆屏 face 页、对话进行中 |
| 暗室聚焦 | 深底 + 单一光源照亮主体 | 夜间模式、对话页 |
| 标本目录 | 条目以清单/网格整齐排列，信息密度高 | 设备与底座、图库 picker |
| 杂志排版 | 栏式布局、大小字号对比强烈 | 「我的」页、说明文档类页面 |
| 一个母题贯穿 | 单一形状/圆角/线条元素反复出现 | 全局视觉语言（我们已用圆 = 圆屏母题） |
| 产品自己说话 | 让真实内容/数据占据主视觉 | 车辆数据卡、对话历史 |

选定方向后写代码时要能回答：**这个页面如果和别的 App 撞脸，它靠哪个元素被人认出来？** 答不出来就说明还在模板里，重新想。

## 2. 「AI 味」检查清单（Compose review 用）

taste-skill 用真实浏览器三档宽度自检 slop。我们改成提交前的 checklist，每个新/改页面过一遍：

### 布局
- [ ] 没有文字或可点击元素贴着屏幕物理边缘（≥ 16dp 边距；圆屏曲边区域 ≥ 24dp）
- [ ] 左右边距对称（除非方向本身要求不对称，且是有意的）
- [ ] 空白分布均衡——不是「上面挤成一团、下面一大片空」
- [ ] 圆屏（410×502）上关键元素不出曲边裁切区

### 层级
- [ ] 一页只有一个主视觉重心；次要信息有明确的字号/透明度阶梯
- [ ] 标题、正文、辅助文字至少差两级，不允许全部同字号
- [ ] 颜色不超过 1 个主色 + 1 个强调色 + 中性色阶

### 交互
- [ ] 可点击区域 ≥ 48dp（手机）/ ≥ 56dp（圆屏）
- [ ] 状态变化有反馈（loading / 空态 / 错误各有真实文案，不用占位文本）
- [ ] haptic + liveRegion 已按 1.25.0 约定加上

### 「生成感」专项
- [ ] 没有紫蓝渐变 + 圆角白卡的默认组合
- [ ] 图标风格统一（不混用填充/描边两套）
- [ ] 占位插画、装饰性 emoji 为零
- [ ] 文案说人话，不出现「立即体验」「赋能」这类话术

## 3. 截图自检（对应 taste-skill 的浏览器三档自检）

2. 圆屏档（410×502）：`RoundScreenRenderTest` 产出 `build/screenshots/round-*.png`，
