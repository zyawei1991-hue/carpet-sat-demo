## 1. 发声落点：设了圆屏出声，还是手机在响（P0 · bug）

**症状**：owner 在齿轮面板把「由哪个设备发声」选成圆屏，答句仍从手机喇叭出；且 owner **看不到**设置页那行"为什么在手机念"的红字。

**现状代码（逻辑本身是对的）**：
- `ScreenVoice.answerHere()`（`ScreenVoice.kt:104`）= `device==phone || link==null || !link.audioReady`。
- `playNetAnswer()`（`ScreenVoice.kt:594`）按 `wantScreen` **互斥**地推屏或本机放；`audioReady = negotiated≥3 && 连接 open`（`ScreenLinkServer.kt:202`）。
- 那行红字 = `voiceIssue`，`HomeShell.kt:330` **只在非 null 时渲染**。owner 看不到 = 此刻 issue 是 null。

**矛盾点（要查的就是这个）**：若路由真把这句判给手机（`wantScreen=false`），`playNetAnswer` 会返回 `PhoneOnly` 并 set issue（`whyNot`）。issue 却是 null ⇒ 两种可能：
1. **装机 APK 旧于 1.29.1**——旧版 `NetResult.Both`（推屏 + 本机同播同一句、不记 issue）就是 this bug，repo 已修但没装机；
2. 有一条本机播放路径没记 issue。

**要求**：
1. 先确认装机版本号；repo 的互斥路由修复若没装机，**重新打包装机先验一遍**。
2. **手机喇叭只要响了，就必须有一行可见原因**（把 issue 设上，别让"手机在响但界面说一切正常"）。建议在 `speak` 那一刻打一条 log：`answerDevice / audioReady / negotiatedVersion / origin`，现场能回读定位。
3. 屏起头那一轮（`origin=screen`）永远只屏念、不受设置影响（已实现，别回归）。

**验收**：选圆屏 + 屏在线≥v3 ⇒ 只屏出、手机一声不出、issue=null；选这台手机 ⇒ 只手机出、屏一帧 `audio_chunk` 不收；屏没连/＜v3 ⇒ 手机出**且设置页有可见原因**。

**屏侧**：播放本身好的（owner 实测出声/情绪 OK），不动；配合回读 `hello.protocols`。

## 2. 对话要分场景，别全是卫星（P1）

**症状**：不管在哪个场景，对话都围绕"卫星过顶/终端在线"。owner：卫星只是车载极少数情况用的。

**根因（App 对话大脑四处都是卫星味）**：
- 系统提示词身份写死「你是车宠守护助手」（`Providers.kt:408` SYSTEM）。
- 喂模型的事实表 `AiGateway.summarize()`（`AiGateway.kt:129`）**无论场景**全是 相位/过顶/终端/待发/围栏/定位——模型手里只有卫星事实，自然只谈卫星。
- 技能关键词与建议（`Skills.kt:109`「过境/过顶/卫星」、`NO_MATCH`「链路/过境/额度/车在哪」）、guard 兜底（`AiGateway.kt:119`「我只能确认卫星这一侧的状态」）都卫星味。
- 场景只有 `TurnScene{vehicle,family}`（`Conversation.kt:37`），`screenSceneOf`（`:44`）只映射 vehicle/kids，**助手/对话态→null**，掉回默认卫星。

**要求**：
1. 场景补全：车（守护）/家（亲子）/对话（助手）三态各有标签。屏已报当前页（`page_report`→`screenPage`），`screenSceneOf` 把 avatar/对话页映射到助手态。
2. **按场景换系统提示词身份 + 事实表 + 技能**：亲子→育儿陪伴（故事/成长/额度，事实给亲子相关、**不喂卫星**）；助手→通用问答；车载→守护，且**卫星只在车主问起或真有守护事件时谈**，不主动满屏卫星。
3. 主动提示（`Heartbeat`）也分场景：亲子态别播"卫星终端不在线"。

**边界**：不加新 frame；场景标签屏已用 `page_report` 报、不用新协议；**不假造亲子内容**（没有的事实说没有）。

**验收**：亲子页问一句 ⇒ 育儿味不是卫星味；助手态通用问答；车载态问卫星才答卫星。

## 3. 情绪要跟着场景/对话走（P1 · 与 §2 同根）

**owner 问**：情绪是啥、怎么获取。
**答**：情绪 = 数字分身那张脸的表情（中性/开心/兴奋/难过/担心/犯困/思考）。链路：**App 算 → `state.ui.emotion` → 屏画**（屏侧已落地、owner 实测 OK）。

**现状**：App 算情绪主要看卫星/守护（`CardPolicy.kt`：终端在线 happy / 离线 sad / 越界呼救 worried / 戳 excited / 动静 thinking）+ 答句语气（`AnswerMood`）。所以情绪也卫星味。

**要求**：情绪按场景/对话内容算——亲子→温暖/俏皮，助手→中性/思考，对话→跟答句语气；守护态才用担心/着急。屏侧渲染不动，**App 改 `CardPolicy`/`AnswerMood` 的判据把场景纳进去**。

**验收**：亲子页对话时脸是温暖/俏皮，不是卫星离线那张难过脸。

## 4. 长答按句分段念（P1 · owner 已拍折中）

**症状**：长答只讲一半。
**根因**：SYSTEM 写死「用一句话回答，不超过30个字」（`Providers.kt:409`）+ `max_tokens:250`（`:389`）。长答被压成半句或被 250 token 截断。这是 11-11「压缩答句」口径的副作用。

**owner 裁决**：折中——**长答按句分段念：第一句先出来（快），后面接着念完**。

**要求**：
1. 放宽「≤30字」硬上限：允许长答，但仍言简意赅（压缩风格保留，不再一刀切 30 字）；`max_tokens` 相应抬到够念完一段。
2. **按句流式 TTS**：答句拆句 → 第一句合成 → 立刻推屏 → 后续句边合成边推。降低首句出声延迟、长答念全。
3. 推屏契约不变：`audio_chunk` **同一 `turn_id`、`seq` 跨句连续**；屏按 seq 重组顺序播。每帧编码后 ≤3800 字节。

**屏侧配合**：核播放重组对"同 turn_id 长流/多句"无丢帧无早停（#14 已修 prebuffer 只在开口前；长流复称）。

**验收**：问一个需要长答的问题 ⇒ 第一句很快出声、整段念完不断尾；短答仍快。
